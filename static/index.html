publish a skill

        
A skill is a folder with a SKILL.md at its root — YAML front
        matter giving name and description, then the instructions. Any
        other files ride along: scripts, templates, vendored source, prebuilt binaries.

        
The machine this runs on has no internet, so a skill carries what it
        needs. Python dependencies go in wheels/ with a requirements.txt;
        they are installed with --no-index, which never reaches the network. Anything
        compiled ships as source under src/ with a Makefile, or as a binary under
        bin/. A skill that would have to download something at install time is not
        finished.

what this is

        
Two jobs behind one address. ocr turns a scan, a photo or a
        300-page PDF into text — tables come out as markdown, and a page with a chart or a
        drawing also gets a short note describing it. knowledge is the team's own
        notes: 0 of them, searchable, and anyone can add more.

        
The card holds one model at a time. Whichever job you start loads its
        own, which costs a second or two; plain search loads nothing and is instant.

      


      
giving it to a model

        
The point of the prompt is that you stop being the one who looks things
        up. Paste it into Claude Code, ChatGPT, Cursor or anything that can run a command,
        and that model gets the library as a tool — it searches, opens the articles it needs,
        reads your PDFs and writes new notes back, without you in the middle.

        
It is one paste. The prompt already carries this server's address and
        the one-line command that fetches the client, so the model sets itself up on first
        use. Nothing is installed here and nothing is installed there beyond a single file.

        

          
          
        

      


      
the three levels

        
Asking costs time, and most questions do not need the model at all.
        The prompt tells the agent to start at the cheapest level that answers the question.

        
searchNo model, under a second. Titles and scores, the
          way a grep over the library would look.

        
fetch — the useful oneThe small model is shown the
          shortlisted titles and picks which are worth opening; you get those articles in
          full, with their source links. Nothing is paraphrased, so nothing is invented.
          A few seconds. A big model reads the source better than a small one summarises it,
          which is why this is the one to prefer.

        
askThe small model picks, reads and writes the answer
          itself, citing [#id]. 20-90 seconds. Worth it when you want the answer
          rather than the sources — and when it says the notes do not cover something, they
          genuinely do not.

      


      
skills

        
A skill is a folder with a SKILL.md at its root: front matter
        naming it and saying when it applies, then instructions another model follows. Scripts,
        templates and vendored source travel with it.

        
This machine has no internet, so a skill carries what it needs. Python
        dependencies sit in wheels/ and install with --no-index, which
        never reaches the network; anything compiled ships as source or as a binary. Installing
        writes files and runs nothing — taking somebody's scripts onto your machine should
        be a decision, not a side effect, so --with-wheels is the explicit opt-in.

        
python3 minitoolkit.py skill list
python3 minitoolkit.py skill install stm32-debug --with-wheels
python3 minitoolkit.py skill publish ./my-skill

      


      
keeping a copy

        
The sidebar has two links. database is the exact backup, taken
        through sqlite's own backup so a write in flight cannot tear it; put it back by stopping
        the server and copying it over data/notes.db. markdown is a zip with
        one readable .md per note plus a library.json holding the fields
        markdown cannot carry. There is no way to fetch any of this again, so take one.

      


      
over http

        
Anything the client does is a plain POST, if you would rather call it
        directly:

        
curl -s -X POST /api/v1/ask \
  -H 'Content-Type: application/json' \
  -d '{"question": "how do we wire SWD?", "mode": "direct"}'

        
mode is direct for the articles or
        summary for a written answer. /api/v1/search,
        /api/v1/ocr and /api/notes cover the rest; every reply is
        JSON.

      


      
reading documents

        
Roughly 30 seconds a page. A 20-page PDF is ten minutes, which is
        longer than most agents' command timeout — the prompt tells them to run it in the
        background and tail the log rather than kill it and start again. Pages queue, so a
        second job waits instead of fighting for the card.

        
Drop files on the ocr tab to do it by hand. Numbers always come
        from the text itself; the figure note is only there to explain the shape of a drawing,
        never to restate a value.

      


      
adding what you know

        
Under knowledge → add. The title and tags carry most of the
        search weight, so name a note the way someone would ask for it — "flashing firmware
        over serial" finds its way home, "notes 3" does not. Anything written here is
        immediately visible to every model pointed at this server.

        
There is a second prompt for the opposite direction. knowledge → add
        has copy writing prompt: give that to a model with a subject and it researches it
        and returns a finished guide in this library's shape — numbered sections, fenced code
        with the indentation kept, real tables, callouts, and its sources. Save the reply as a
        .md file, drop it on the same tab, and it is parsed, shown for review and
        saved. Several files at once is fine; a file with nothing under its title is refused
        rather than stored empty.

        
So: copy LLM prompt hands the library to a model,
        copy writing prompt gets a document out of one, and the
        skills tab has a third that gets a whole packaged procedure out of one.

        
knowledge → notes browses what is already here: the decks, then
        a deck's guides, then the guide itself with its tables, code and callouts rendered.
        Notes written here sit under their own deck rather than disappearing among the
        imported ones.
